### A third declared run, a long page uncompressed and with a browser's encodings: the plan, written before the run

The third review, of `e8d32b541`, found that every no-regression margin so far is on the 9,793-byte page, which takes no page fault at either limit, and that a long page with `identity` or with a browser's encodings was never run under load, though the limit keeps any buffer of 64 to 512 KiB and CONTRIBUTING says an unaffected route does not count. This plan runs it. It is written after the second run's results are known and reads nothing of that run again; it does not bear on the first run's miss, which stands.

1. The protocol and the scripts are the second run's, unchanged (`tc-pair3.sh`: the app on the host's network, pinned to one CPU with one runtime, `wrk -t2 -c64` on two other CPUs, `perf stat -e cycles:u,cycles:k,instructions:u` from a fourth, each turn a freshly started container, 2 s of warm-up and a 3 s run inside a 3.4 s count, the settings' order turned every pair), on the same image on the two c-16s with a Xeon Platinum 8280 that ran the second run's `identity` and `gzip, deflate, br, zstd` workloads. Only `MALLOC_CONF` differs between the sides.
2. No regression, held to +1% with no floor, 200 recorded pairs after one that is not, each: the 202,041-byte page with `identity` on the first host and with `gzip, deflate, br, zstd` on the second. The bound is the 113th of the 200 sorted per-pair changes in user plus kernel cycles a request.
3. What the run can resolve: before each, on the same host, 64 KiB against 64 KiB under two labels on the same workload, 200 recorded pairs after one that is not, read as recorded and with the labels swapped. If either bound is at or above +1% the workload is not resolved, which does not pass whatever its comparison's bound.
4. No turn of these workloads has been run on the host's network, and none runs before this plan is in this description: there is no trial of the script this time. Each comparison runs once, whatever the one before it showed; none is run again and no pair is dropped for its result. The two settings' answers are compared byte for byte but `Date` and `ETag` before each comparison.
5. A margin not met or a workload not resolved is reported as that and stands against the change on that workload. Whatever this run shows, it does not decide whether the change merges: the third review holds that to be the maintainer's decision.

Not planned: the 32,501-byte and 495,521-byte pages with these encodings; a client with gzip alone; pages past 496 KB; more than one runtime; a host with another CPU.
