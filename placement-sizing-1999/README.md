# Placement sizing (corten-run/corten#1999 and #1996): what was measured, and with what

One run of kit 1999 on a quiet c-8 (DigitalOcean, Intel Xeon Platinum 8280, Debian 13, Linux
6.12.117), run `8068ffb8-4604-431d-af08-717236923d24`, finished 2026-11-24. Nothing else ran on
the host, and it has been deleted. The plan's sha256 is
`c4eccf95500982be218107356b0f1edeb0ecd29d293697b2fb0abf4da88db50d`; the tar the host unpacked
has sha256 `1e88851e338fea089d0a5808224312ee92cb7b1edc938a601998819337a584d4`
(`results/kit-sha256.txt`); the archive the results were collected in has sha256
`bce00a39ede21ebf90b4d01c7f0142993f06561e92f6b2fbb53639b48efff818`.

It measures the placement apparatus of design Choice 72, not any change: part A, an A/A of base
`14126d2a8` against itself at K = 100 placements of 8 pairs on the workload `old`; part B (one pad
list against itself), cut for time before the run; and part C, four unpadded builds (base, head
`8d02090bf`, `92bc32678` and `705d14045`) each against eight padded ones.

## The kit

`kit/` is the tar's `1999/` directory: `plan.md` (the plan, declared before any measurement, with
its one amendment), `plan.env`, `commits.env`, the scripts (`setup.sh`, `build.sh`, `verify.sh`,
`run.sh`, `run-pair-old.sh`, `report.mjs`, `model.mjs`, `size.mjs` and the rest), the probe
program, `prior/` (the first two placement runs' CSVs, from tags `evidence/ee7b0b41` and
`evidence/0c0c599c`), `analysis/` and `dry-run/`, a container dry run with a stand-in for `perf`,
marked `DRYRUN` and read for nothing. `kit/README.md` says what each file is.

Left out: `src-base/`, `src-head/`, `src-x1/` and `src-x2/`, each a `git archive` of `crates
examples Cargo.toml Cargo.lock .cargo` at the commit in the matching `src-*.commit`. They are
copies of the repository at those four commits (all four on `main`'s history or under
`refs/tags/evidence/`); each tree's file count, `Cargo.lock` and `crates/corten/src/lib.rs` were
checked against Git before they were left out, and `results/kit-sha256.txt` holds a hash of each
tree as the host read it.

## The results

`results/` is the host's results directory as collected, nothing removed:

1. `report.md` (and `report.json`): the reading, generated by `report.mjs`. Start here.
2. `aa-old/pNNN/` and `unpadded-<side>/pNN/`: a placement's `counts-old.csv` (every recorded
   pair's requests and counters), `placement.txt` (kit, run, plan, its place in the schedule and
   its binaries by sha256) and the turn logs.
3. `schedule.txt`, `progress.log`, `run.log`, `retries.txt` (empty: no placement failed): the
   order the placements ran in, and the logs.
4. `host.txt`, `host-id.txt`, `sha256.txt`, `placements.txt`, `placements-summary.txt`,
   `layout/`, `link-*.json`: the host, the binaries and where each placement's functions landed.
5. `verify/`, `verify.log`, `check-only/`, `check-only.log`, `preflight/`: each padded binary
   answering as its unpadded one, and the checks before the run. The 2,776 saved answer bodies
   are one PNG of 8,000 bytes, so Git stores it once.

Git stores the kit's text files with the repository's line endings, so a file the dry run wrote
with CRLF reads as LF here.
